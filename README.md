# Мій стан

Дашборд тренувань, сну, кроків і ваги, побудований з історії Garmin.
Живий сайт хоститься на **Vercel** (так само, як monobank-vercel); дані
щоночі підтягуються автоматично через GitHub Actions — GitHub-репозиторій
тут потрібен не для хостингу сторінки, а для того, щоб було де жити
Actions-автоматизації (Vercel сам крону не має).

## Структура

```
index.html                        — сама сторінка (читає data/dashboard-data.json, data/workout-log.json)
data/dashboard-data.json          — усі дані графіків
data/workout-log.json             — повний лог тренувань: кожна сесія, кожна вправа, кожен підхід
data/recovery.json                — щоденний знімок відновлення (кроки, сон, HRV, Body Battery, стрес,
                                     training readiness — усе, що вдалось витягти з акаунта)
scripts/fetch_garmin.py           — щоденний скрипт оновлення (запускає GitHub Actions)
scripts/generate_garmin_session.py— одноразовий локальний логін у Garmin
scripts/update_weight.py          — приймає дані ваги від Shortcuts-автоматизації
.github/workflows/daily-update.yml— cron-завдання (Garmin, щодня о 05:00 UTC)
.github/workflows/health-weight-update.yml — приймає виклик від Shortcuts (Apple Health)
```

### Журнал тренувань і дані для наступного плану

`fetch_garmin.py` щодня само дописує нові сесії в `data/workout-log.json` (усі
вправи й підходи, а не лише 4 основні графіки) і новий день у
`data/recovery.json` (кроки, сон, ЧСС спокою, HRV, Body Battery, стрес,
training readiness — best-effort: якщо якийсь показник не приходить із
Garmin для цього акаунта/пристрою, поле просто пропускається, скрипт не
падає). Обидва файли існують саме для того, щоб дані для наступного
тренування завжди були свіжими без ручного запиту.

Сама генерація плану на наступне тренування лишається ручним кроком:
попроси в чаті (наприклад, «склади тренування на сьогодні на основі
попередніх») — це навмисно не автоматизовано GitHub Actions, щоб план
завжди проходив через живий перегляд, а не публікувався сам.

## Встановлення (один раз)

### 1. Створи репозиторій

На github.com → New repository → назви, наприклад, `my-state-dashboard` →
Create. Публічний або приватний — обидва підтримують GitHub Pages
(приватний потребує GitHub Pro/Team, якщо хочеш хостити сайт з приватного
репо; якщо це проблема — зроби репо публічним, там немає нічого
чутливішого за дати й ваги підходів).

Заливаєш цю папку туди звичним чином:

```bash
cd my-state-dashboard   # папка з цими файлами
git init
git add .
git commit -m "init: Мій стан dashboard"
git branch -M main
git remote add origin git@github.com:<твій-акаунт>/my-state-dashboard.git
git push -u origin main
```

### 2. Задеплой на Vercel

Так само, як з monobank-vercel — двома шляхами, обери зручніший:

**Варіант А — через CLI (як тоді):**
```bash
cd my-state-dashboard
npx vercel login      # одноразово, браузерний логін — я тут ні до чого
npx vercel --prod     # деплоїть поточну папку
```
Vercel видасть URL типу `my-state-dashboard.vercel.app`.

**Варіант Б — через vercel.com (без CLI):**
New Project → Import Git Repository → обери щойно запушений репозиторій
→ Deploy. Framework preset можна лишити «Other» (це статичний HTML, білд
не потрібен). Плюс цього варіанту: Vercel сам передеплоїть сайт щоразу,
коли GitHub Actions закомітить нові дані — не треба нічого додатково
тригерити.

**Якщо обрав варіант А** (деплой напряму з CLI, без git-інтеграції) —
Vercel не дізнається про майбутні коміти самостійно, тож щоденний
workflow сам смикне redeploy. Для цього:
- Vercel → твій проєкт → Settings → Git → Deploy Hooks → створи хук
  (гілка `main`), скопіюй URL.
- GitHub репо → Settings → Secrets and variables → Actions → New repository
  secret → `VERCEL_DEPLOY_HOOK_URL` → встав туди цей URL.
- Це не токен доступу до акаунту, а односторонній «подзвони мені» URL —
  безпечніше за API-ключ, але все одно постав секретом, а не в код.
Якщо секрет не додати — сайт просто доведеться передеплоювати вручну
(`npx vercel --prod`) після нових даних; усе інше працюватиме.

### 3. Згенеруй сесію Garmin (локально, не тут)

Цей крок ти робиш **сам, на своєму комп'ютері** — пароль від Garmin ніколи
не повинен проходити через Claude чи опинятися десь у чаті чи файлі, який
я бачу.

```bash
pip install garminconnect
python3 scripts/generate_garmin_session.py
```

Скрипт запитає email/пароль (і код з MFA, якщо він у тебе увімкнений) прямо
в терміналі, увійде в Garmin один раз і збереже токен сесії у
`~/.garminconnect`. Далі щоденний скрипт користується цим токеном і більше
ніколи не питає пароль — і не викликає MFA щоразу.

Скрипт запакує токен у файл `garmin_session_secret.b64` у поточній папці.

### 4. Додай секрет у GitHub

Repo → Settings → Secrets and variables → Actions → New repository secret:
- Name: `GARMIN_SESSION_B64`
- Value: весь вміст `garmin_session_secret.b64`

Після цього видали `garmin_session_secret.b64` зі свого комп'ютера — це,
по суті, жива сесія, тримай її як пароль.

### 5. Перевір вручну

Settings → Actions → General → переконайся, що Actions увімкнено для
репозиторію. Потім Actions → Daily Garmin data update → Run workflow —
запусти вручну один раз і подивись лог: чи знайшлись кроки/сон/тренування
за вчора, чи є помилки.

### 6. Автоматизуй вагу/склад тіла з Apple Health (опційно)

GitHub Actions **не може** сам піти й прочитати Apple Health — Apple не дає
для цього жодного хмарного API (на відміну від Garmin, де є акаунт з API,
куди годинник сам все синхронізує). Дані завжди повинен надіслати сам
iPhone. Робимо це через застосунок **Команди (Shortcuts)**:

**6.1. Створи GitHub-токен для цього одного завдання**

GitHub → аватар → Settings → Developer settings → Personal access tokens →
Tokens (classic) → Generate new token → скоуп лише `repo` → створи й
скопіюй токен (він більше ніде не покажеться, збережи в Нотатках/Паролях,
не в чаті).

**6.2. Створи автоматизацію в Командах на iPhone**

Команди → вкладка «Автоматизація» → «+» → «Створити особисту автоматизацію»
→ **Час доби** (наприклад, щовечора о 21:00) → Далі → **вимкни** «Запитувати
перед запуском» (інакше вимагатиме підтвердження щоразу) → Додати дію.

Дії всередині автоматизації (по черзі):

1. **«Показник здоров'я»** (Health Sample) → тип «Вага тіла» → діапазон
   «Останній запис» → результат поклади у змінну, наприклад `Weight`.
2. Повтори те саме для «Відсоток жиру в тілі» → змінна `BodyFat`, і
   «Пісна маса тіла» → змінна `LeanMass` (якщо Xiaomi їх пише в Health —
   якщо якогось показника нема, просто пропусти цей крок і відповідне поле
   в наступному JSON).
3. **«Поточна дата»** → формат `YYYY-MM-DD` → змінна `Today`.
4. **«Отримати вміст URL»** (Get Contents of URL):
   - URL: `https://api.github.com/repos/<твій-акаунт>/<репо>/dispatches`
   - Метод: POST
   - Заголовки:
     - `Authorization` → `token <твій токен з кроку 6.1>`
     - `Accept` → `application/vnd.github+json`
   - Тіло запиту (Request Body → JSON), поля:
     - `event_type` → `health-weight-update`
     - `client_payload` (Dictionary) →
       - `date` → змінна `Today`
       - `weight_kg` → значення показника ваги (число з `Weight`)
       - `lean_mass_kg` → значення з `LeanMass` (якщо є)
       - `body_fat_pct` → значення з `BodyFat` (якщо є)

Збережи автоматизацію під назвою, наприклад, «Синк ваги в дашборд».

**6.3. Перевір**

Запусти автоматизацію вручну (натисни на неї в списку → Запустити).
Перевір Actions на GitHub — має з'явитись запуск «Apple Health weight
update», і після нього — новий коміт з оновленим `data/weight`.

Якщо телефон офлайн увечері (наприклад, заряджається без інтернету) —
запис за той день просто не прийде; наступний вечірній запуск надішле вже
свіжіший, тож пропуск одного дня не критичний.

## Якщо щось піде не так

- **Auth error / сесія протухла** — рідко (зазвичай тримається місяцями),
  але якщо станеться: перезапусти `generate_garmin_session.py` локально й
  онови секрет `GARMIN_SESSION_B64`.
- **Назви методів у `garminconnect` розійшлися** — цей скрипт писався й
  перевірявся на синтаксис без живого доступу до Garmin (я, Claude, не мав
  і не повинен мати твій пароль). Якщо якийсь виклик (`get_steps_data`,
  `get_sleep_data`, `get_activities_by_date`, `get_activity_exercise_sets`)
  впаде з `AttributeError` — подивись у трасуванні точну назву методу у
  встановленій версії пакета (`pip show garminconnect`) і виправ виклик у
  `scripts/fetch_garmin.py`; решта логіки (класифікація вправ, дозапис у
  JSON) залишається без змін.
- **Правило для Bench Press**: у графік потрапляє лише жим штангою
  (`BENCH_PRESS` без "DUMBBELL"/"MACHINE"/"SMITH" у назві вправи). Дні, де
  був лише гантельний жим (наприклад, тренування типу А2), автоматично не
  додають точку в цей графік — це очікувано, не помилка. Виключені підходи
  пишуться в `bench_excluded_variants` і показані окремою таблицею внизу
  сторінки для прозорості.
- **Vercel не оновився після нового коміту** — перевір, чи додав секрет
  `VERCEL_DEPLOY_HOOK_URL` (крок 2) або чи під'єднав репозиторій до Vercel
  через Git-інтеграцію (варіант Б у кроці 2). Без жодного з двох новий
  `data/dashboard-data.json` буде в GitHub, але стара версія лишиться на
  сайті, доки не задеплоїш вручну.
